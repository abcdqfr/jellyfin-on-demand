# ADR-002 (swarmplay): O6 virtual items + O7 VLC-shaped process lean

**Status:** Accepted

**Date:** 2026-07-20

## Context

Need a host for play (O6) and a place for libtorrent (O7). Prior art:
[vlc-bittorrent](https://github.com/johang/vlc-bittorrent) loads as **in-process
VLC modules** and keeps a **shared `lt::session`** (weak_ptr singleton + alert
thread) for the player process — not a sidecar daemon.

MVP product path: TMDB/TVDB → title → ranked Torznab/magnet → warm → Play on a
plugin-owned item (optional “I’m feeling lucky” = rank #1). Library scanner /
stub files are optional debt.

## Decision

1. **O6a locked (MVP):** Virtual items — plugin-owned; abandon JF library rows
   for this product. Virtual still carries a growing-file **Path** at Play
   (O2a); it means no FS library identity.
2. **O7a locked (MVP lean):** Follow vlc-bt — libtorrent lives **in the Jellyfin
   process** (native bridge / P/Invoke as needed). Shared session for the
   server process lifetime, same spirit as vlc-bt’s `Session::get()`.
3. **O7b on roadmap, not MVP:** Sidecar `swarmplayd` later for isolation /
   shared-session ops. Cherry-pick strmarr examples for cache prefs / seeding /
   daemon-shaped session management when that work starts.
4. **O7c demoted:** Not the lean. Per-play exec is not how vlc-bt works.

## Consequences

- MVP packaging ships a native libtorrent dependency loadable by JF; crash
  domain is JF (accepted for MVP; O7b is the isolation upgrade).
- Plugin control plane may stay in-proc (no HTTP daemon required for MVP).
- Roadmap explicitly includes O7b; do not block MVP on sidecar.
