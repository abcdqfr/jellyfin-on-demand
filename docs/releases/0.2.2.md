# Swarmplay 0.2.2 (virtual-item probe fix + history UX)

Hotfix tier: 0.2.1 warmed the right bytes, but audio/subs still didn't show
up on a cold play of a real movie. This release fixes the actual break — one
layer above the extent gate — and replaces the search-history UI with a
browser-address-bar-style dropdown.

## Highlights

- **Root cause found and fixed:** `BindVirtualMovieAsync` minted the bound
  `Movie` item with `IsVirtualItem = true`. Jellyfin's
  `MediaBrowser.Providers.MediaInfo.ProbeProvider.FetchVideoInfo`
  unconditionally skips ffprobe for any item flagged virtual — *regardless*
  of `MetadataRefreshMode` — so `MediaStreams` stayed `[]` forever and
  PlaybackInfo/ffmpeg fell back to no explicit stream maps (`-sn`, no
  `-map`) even though the file itself had real audio/subtitle tracks warm
  on disk. This is exactly why "no improvement" was reported after the
  ADR-007 (0.2.1) extent gate shipped: the gate was correct, the item
  metadata was the actual bug.
- **Fix:** bound items are real playable files (the growing torrent file),
  not placeholders — `IsVirtualItem = false` on both the create and update
  paths. Added an explicit `RefreshMetadata(MetadataRefreshMode.FullRefresh)`
  call in `BindVirtualMovieAsync`, right after the extent gate confirms
  head+tail are warm, but only when `item.GetMediaStreams().Count == 0` so
  replays of already-probed items don't pay for a redundant ffprobe.
- **Verified live** against a real torrent (*This Is England*, 2006, 5+ GiB,
  16 MiB pieces): `MediaStreams` went from `[]` to 1 video (HEVC) + 2 audio
  (AAC 5.1 / stereo) + 1 subtitle (PGSSUB) stream on the very next play-bind.
- **Regression guard:** `scripts/offline_client_integrity_check.py` now
  fails the gate if `IsVirtualItem = true` reappears in `SwarmController.cs`,
  or if the post-gate `RefreshMetadata(FullRefresh)` call is removed.
- **History UX:** replaced the omnipresent floating **History** button +
  modal with an inline dropdown anchored to the native Jellyfin search field
  (`#searchTextInput`) — opens on focus/typing, closes on blur/Escape/
  outside-click, per-entry remove (−) button, one "Clear history" action.
  Nothing is left on screen when the search field isn't focused.
