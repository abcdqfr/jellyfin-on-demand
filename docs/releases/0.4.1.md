# Swarmplay 0.4.1 (hotfix: Stream = real .strm, warm-progress bar, blazing-ahead regression)

Hotfix on top of 0.4.0 (cache-to-library). Corrects "Add to Library →
Stream" to actually do what it says, and fixes a real warm-time regression
introduced by the blazing-ahead readahead-window mitigation.

## Highlights

- **Add to Library → Stream writes a real `.strm` pointer** (strmarr-style),
  not a bare alias of the plain Play button. New `POST
  Swarmplay/swarm/stream-bind` ([ADR-010](../adr/010-strm-add-to-library-v0.4.1.md)).
  Play and Lucky are unchanged — still always a real growing-file virtual
  item, never a placeholder.
- **Blazing-ahead readahead-window regression fixed:** the window was sized
  in raw piece count (`+48` pieces) and could balloon past a gigabyte on
  large-piece-length torrents. Bounded in bytes instead
  (`kReadaheadFloorBytes`, 24 MiB).
- **Real warm progress bar:** `swarm_status.progress` now reports
  tail+head[+readahead] completion fraction (`warm_progress`), not raw
  libtorrent torrent progress. The client warm overlay polls it into an
  actual percentage + peer count wherever btih is known up front.
